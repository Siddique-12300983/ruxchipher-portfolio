Kerberoasting: attack & detect

Event ID 4769

A service account with an SPN is set up on purpose. I request its ticket from Kali, then hunt for that request in the domain controller's Security log.

Red

Register an SPN, request a TGS for the service account from Kali.

Blue

Catch the request as Event 4769 on the DC.

Purple

Tune the detection, then harden the account.

DC · PowerShell
# hunt: service ticket requests using RC4 PS> Get-WinEvent -FilterHashtable @{ LogName='Security'; Id=4769 } | Where-Object { $_.Message -match '0x17' } # 0x17 = RC4-HMAC, a classic Kerberoasting tell

sentinel: host alerting

blue team

A Python service I wrote that runs in the background and sends a desktop alert when something looks wrong.

  • Follows the systemd journal for failed passwords: sudo, admin prompts, the login screen and SSH.
  • Polls listening TCP ports and flags any new one, marked critical if it's reachable from the network.
  • De-duplicates repeats and writes every alert to a log for review.
events.log · my own test run
[!] Failed password | source: sudo [!] New listening port (network-exposed) 0.0.0.0:48765 · process: python

ruxchipher HUD

Lua · cairo

Four desktop widgets drawn from scratch in Lua with the cairo graphics library, running on Conky.

  • Battery-aware GPU polling: checks the GPU's power state first, so the monitor never wakes the RTX 4060.
  • Live lab status: reads virsh domstats to show which VMs are running and how busy they are.
  • Mission tracker: my 2027 goal, lab objectives and a commit streak pulled from my lab repo's git history.
  • Sentinel strip: pulses red after an alert; one click opens a plain-language report of what happened.
  • Battery-friendly animation: the weather icon only animates when clicked, or for a few seconds every 10 minutes.
